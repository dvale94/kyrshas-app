## Recommended next pilot: 04B vertical chapter navigation

Propose **`afterglow-vertical-chapter-paging`** next. Build only the five-position paging shell around the existing synthetic content and typed provider/hook seam, with stable mounted slots, settled progress, explicit Previous/Next and overflow reading mode. Use neutral readable surfaces/current placeholders; exclude final typography/art, rich motion, new packages, native/config/provider changes and production calls.

The decisive risk is reading and navigation sharing the vertical axis. Resolve it with a real compact-iPhone test before investing in illustration. Acceptance must show all five positions in exact ID order; bounded first/last behavior, cancelled/fast drags and explicit navigation; largest-type complete question/answer/author; overflow swipes scroll text rather than pages; revisit retains shown answer; only successful trivia refresh resets it. If built-in behavior cannot meet those criteria, stop with evidence and a separately approved package/native plan, rather than expanding 04B.

## Invariants carried by every pilot

- Exact IDs/order `quote`, `trivia`, `fact`, `dad joke`, `bucket list item`; title/author/answer validation and optional local-placeholder contract remain intact. All five loads independently start; no page-triggered extra request or uniqueness guarantee.
- Retain duplicate/stale protection, last-good content, safe isolated errors, explicit scoped retry and trivia successful-revision reset, including repeated content. Navigation/revisit/failure do not reset an existing answer.
- Keep Expo SDK 58, iPhone-only portrait and `com.dvale1994.kyrshasapp`; retain current default/Release security and approved Debug-localhost policy. No release infrastructure, permission change or native regeneration by implication.
- Default and production mock; API Ninjas direct only in existing explicit local-development `live-local` with private gitignored `.env.local`. No credential reading, provider calls, endpoint/filter/transport changes, new backend or production credential work for a presentation pilot.
- Birthday permanently excluded in modern plans/code/tests; legacy source, personal assets, ignored root/modern native trees, separate backup and owner work preserved. Historical “deferred 03E” references grant no new authority.
- No unsolicited completion/persistence/scheduling/streaks/daily uniqueness, remote photos or mandatory tap-to-open. All content stays readable with art/motion absent.

## Evidence required in each future delivery

Before mutation: fetch issue/current main, inspect AGENTS/specs/docs/Gortex context and git status; preserve owner changes and native state without reading secrets. Complete and strictly validate the selected bounded OpenSpec change. Document exact intended file scope and reproducer/acceptance behavior.

During work: keep implementation and meaningful tests together, run the existing modern `CI=1 npm run verify` only in a safe dotenv-disabled, synthetic environment and preserve current scripts/guards. Do not run root legacy Expo commands. Use the existing approved development-loop procedure only when that future issue authorizes native/simulator evidence; never infer permission for generation, Pods or signing from this roadmap.

At delivery: distinguish PASS, FAIL, NOT RUN, BLOCKED; include check exit codes, current source/commit, screenshots or test artifacts where authorized, source/config/native preservation and limitations. Open a draft PR to main with report/handoff and explicit remaining approvals. No merge, deployment, publishing or automatic archive.
