# Agentic development retrospective

This is a working draft for owner review. It describes a human-directed sequence of bounded pilots; it does not assert that the project was implemented autonomously or that every proposed check was completed.

## Roles and decisions

The owner supplied the original motivation, set product direction, reviewed the experience on a phone, decided which work was deferred, and retains merge and final acceptance authority. ChatGPT supported planning and review; Codex carried out scoped implementation and verification work under issue instructions. GitHub issues framed acceptance and pull requests recorded delivery evidence. OpenSpec supplied bounded proposals and tracked tasks. Gortex supported code and impact navigation, with graph coverage and tool results still requiring judgment and verification.

The project moved from the [legacy audit](https://github.com/dvale94/kyrshas-app/issues/1) and [native inventory](https://github.com/dvale94/kyrshas-app/issues/3), through an [isolated modern scaffold](https://github.com/dvale94/kyrshas-app/pull/6), [typed content orchestration](https://github.com/dvale94/kyrshas-app/pull/14), [design specification](https://github.com/dvale94/kyrshas-app/pull/24), [vertical paging](https://github.com/dvale94/kyrshas-app/pull/26), [visual foundation](https://github.com/dvale94/kyrshas-app/pull/28), [immersive artwork and chapter layouts](https://github.com/dvale94/kyrshas-app/pull/30), and [root legacy restoration](https://github.com/dvale94/kyrshas-app/pull/33). The issue and PR records retain the detailed evidence and historical caveats for each stage.

## What the work taught

- Bounded issues and explicit verification made changes reviewable. The [design roadmap](../design/afterglow/implementation-roadmap.md) recorded requirements for evidence, preservation and draft delivery before subsequent work.
- Visual acceptance required human direction and iteration. The initial visual foundation did not fully express the intended design; owner feedback directed the later artwork and chapter refinement. Screenshot evidence helps a reviewer see the result, but does not replace device and accessibility checks.
- The [issue #29 report](../../.agentic/reports/issue-29-afterglow-immersive.md) records refinements after feedback: artwork was made to follow the swipe, and measured reading fit was added with scrolling retained for overflow. Full-display art and the shorter safe-area viewport still travel different distances; the owner accepted that tradeoff on a physical iPhone. A failed largest-text simulator test later passed after refinement. Neither outcome substitutes for a formal assistive-technology or memory audit.
- A proposed separate legacy showcase did not match the owner's intended comparison. The owner redirected the work to restore the original app at the root; [issue #32](https://github.com/dvale94/kyrshas-app/issues/32) and its [delivery report](../../.agentic/reports/issue-32-legacy-showcase.md) preserve the change in direction and subsequent verification limits.
- Security controls also needed human intervention. For [issue #31](https://github.com/dvale94/kyrshas-app/issues/31), automatic approval review rejected the agent's push because remote trust could not be established; the owner manually delivered the change. This was a human delivery intervention, not evidence of an agent bypassing the branch policy.
- Repeated visual captures, verification reports and closeout bookkeeping can become noisy. Future work should decide the smallest useful evidence set and acceptance criteria early, retain failed attempts where they explain a decision, and tie each claimed result to the exact revision and environment.

Owner-reported phone acceptance, local test results and hosted CI are different forms of evidence. In particular, the legacy delivery report says phone feedback preceded a later dependency alignment; it does not establish post-alignment phone acceptance. Formal assistive-technology and performance evaluation, production content infrastructure and standalone distribution remain deferred. See the [legacy delivery report](../../.agentic/reports/issue-32-legacy-showcase.md) for the security and verification boundaries.
